# Digital Gold: Asset Relationship Explorer (portfolio demo)

> **Portfolio demo — synthetic data, not historical market observations.**
> Every price and volatility-index value in this repository is generated by a seeded random process. Nothing here is market
> data, nothing was fitted to market data, and no chart or statistic is a research finding. Not investment advice.

An interactive React dashboard for exploring how pairs of assets move together: rolling correlation, return scatter with OLS
beta, a full correlation matrix and rolling beta, with regime filters, shareable URLs and CSV export.

It is the public edition of a private research project that studies Bitcoin's relationship with traditional assets. The
research edition runs on third-party market data that cannot be republished, so this edition runs the same calculation and
interface code on a synthetic dataset instead.

> **Live demo:** https://digital-gold-explorer-demo.vercel.app
> 
## Features

- **Rolling correlation:** any pair, preset (30/90/252-day) or custom windows, optional Fisher-z 95% band, regime highlighting,
  and a marker for an arbitrary demo split date.
- **Return scatter:** daily, weekly or monthly log returns, points coloured by volatility regime, OLS fit line, correlation with
  an approximate confidence interval, beta and R².
- **Correlation matrix:** all six series; click a cell (or use the keyboard-accessible table) to open that pair.
- **Rolling beta:** beta of the synthetic crypto series on several benchmarks over a chosen window.
- **Regime filters:** Normal / Elevated / Severe days from percentiles of a synthetic volatility index, with editable cutoffs.
- **Plain-English interpretation** generated from the computed statistics, with method notes and limitations.
- **Shareable state:** every setting is encoded in the URL, so links reopen the same view.
- **CSV export** of the plotted data, headed by the synthetic-data disclosure and the settings used.
- Loading skeleton, error and insufficient-data states, keyboard support and a responsive layout.

Pages that depend on research outputs (stress-regime tables, the before/after comparison, source integrity) are shown as
"Not in demo" with an explanation, rather than re-running them on synthetic data.

## Stack

React 19, Vite 8, Plotly.js (cartesian bundle), plain CSS, and the Node.js built-in test runner. No backend: the app is a
static site that loads one JSON file.

## Architecture

```
src/                     shared analysis and UI code (also used by the private research edition)
  lib/                   statistics, returns, regimes, URL state, CSV export, edition switch
  components/            controls, panels, badges, Plotly wrapper, loading and error states
  views/                 explorer (rolling, scatter, matrix) and rolling-beta views
portfolio/               the portfolio edition (its own Vite root)
  index.html, src/       app shell, demo banner, Data & methods page, "not in demo" pages
  public/data/           explorer.json: the synthetic dataset (generated, checked in)
  scripts/               generate-synthetic.mjs, verify-portfolio.mjs
  tests/                 generator, edition and build-verification tests
```

- **Edition switch at build time.** `portfolio/vite.config.js` defines the constant `__DG_EDITION__ = "portfolio"`.
  `src/lib/edition.js` reads it, so the shared code shows synthetic names and wording and never looks up research outputs.
  Because the constant is substituted at compile time, the minifier removes the other edition's wording from the bundle.
- **Separate Vite root.** The portfolio build only sees `portfolio/public/`, which contains only the synthetic dataset.
- **Statistics run in the browser.** Every number shown is computed client-side from the synthetic prices.

## Synthetic data

`portfolio/scripts/generate-synthetic.mjs` writes `portfolio/public/data/explorer.json` from a fixed seed:

- a three-state Markov chain (calm, elevated, stressed) sets the market state each day;
- daily shocks for six series are correlated through a state-dependent correlation matrix (Cholesky factor) and drawn from a
  Student-t distribution with 5 degrees of freedom;
- volatility rises in the elevated and stressed states, and a synthetic volatility index mean-reverts to a level set by the state;
- after the demo split date, the crypto–equity correlation is raised so the before/after views have something to show;
- all drifts, volatilities, correlations and transition probabilities are hand-chosen round numbers in the script.

The series are named as rough archetypes (synthetic crypto, gold, equity, tech, long bond, mid bond). They do not represent
any real asset, index or fund, and the dates are arbitrary labels.

## Quantitative methods

| Statistic | Method |
|---|---|
| Returns | Log returns ln(Pₜ / Pₜ₋₁); weekly/monthly use the last price in each period |
| Rolling correlation | Pearson correlation over a trailing window; reported only when the full window is available |
| Beta | OLS slope Cov(A, B) / Var(B), with R² |
| Uncertainty | Fisher z-transformation (assumes independent returns) |
| Regimes | Linear-interpolation percentiles (default 75th / 90th) of the volatility index |

## Testing and release safety

```bash
npm ci
npm test            # generator, edition and verifier tests
npm run build       # check data → build → verify the built artifact
```

`npm run build` fails unless:

1. `portfolio/public/data/explorer.json` is byte-identical to a fresh run of the seeded generator;
2. the built site contains only the expected files and no inline scripts (the Content-Security-Policy forbids them);
3. the data file is marked synthetic and has no research fields;
4. the page and the bundle carry the synthetic-data disclosure;
5. no file contains a local filesystem path or research-only markers.

The private parent project runs an additional scan of its builds against fingerprints of the restricted research data. That
step, and the data it needs, are not part of this repository.

## Run locally

Requires Node.js 20.19+ or 22.12+.

```bash
npm ci
npm run dev                  # development server
npm run portfolio:generate   # regenerate the synthetic dataset (same seed → same file)
npm run build && npm run preview
```

## Deploy (Vercel)

`vercel.json` configures the build: install `npm ci`, build `npm run build`, output `portfolio/dist`, plus cache and security
headers (including a Content-Security-Policy). Import the repository in Vercel with the root directory set to the repository
root; no environment variables are needed.
